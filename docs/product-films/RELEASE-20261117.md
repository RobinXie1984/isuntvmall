## Byte-range delivery correction

Live acceptance discovered that [Cloudflare Workers Static Assets](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/) ignore Range requests and return the full file, a documented Safari limitation. A small public `/api/product-films/[id]` handler serves only approved manifest IDs and slices the existing ASSETS stream into valid single byte ranges. No new storage service or credential is added. It keeps backpressure/cancellation, validates source length, rejects invalid/stale requests, implements HEAD/ETag/If-Range, and never accepts an arbitrary asset URL. Only the matching static path is fetched through the existing Worker ASSETS binding.

The store's normal asset-first behaviour and other routes are unchanged. Development preview keeps native local MP4 delivery. Additional unit/route cases cover bounds, multi-chunk ranges, suffix/open-ended ranges, 416, 304, HEAD, unknown/stale IDs and upstream failures. Final complete suite: 689 passing tests; type check and Worker build pass. Real 206 checks and playback are recorded after the correction release.

Native asset-binding streams can omit a Content-Length header. The handler uses the trusted same-version manifest length, checks any supplied length, and streams the requested range with bounded memory. Local Worker readback confirms all three byte probes return 206 and invalid ranges return 416.
