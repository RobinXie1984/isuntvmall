## One reusable workflow

1. Read the existing public broadcast registry. Keep IDs, original source URLs, admin visibility, ordering and linked merchandise unchanged.
2. Resolve the actual video through its visible source page; use public download access where supported. Do not export cookies, bypass sign-in restrictions, or guess video IDs from post IDs.
3. Retain an immutable source section, source URL, source time range and SHA-256 on Studio. Inspect real frames and playback. Select a useful try-on or demonstration, with verified brand identity, strictly under 60 seconds. Keep full product shape/straps/heels and colours. Reject footage where removing captions would remove merchandise. Never invent a manufacturer from a shop or blogger name.
4. Prepare a JSON section spec: `id`, `brand`, `sourceUrl`, local MP4 `file`, original `sourceStart`, `seconds`, and integer `crop:[width,height,x,y]`. The source file begins at `sourceStart`; it is a downloaded section, not the entire broadcast.
5. Run `node scripts/prepare-product-films.mjs SPEC.json SOURCE_DIRECTORY NEW_OUTPUT_DIRECTORY`. It refuses an existing output directory, strips audio/subtitles/data/metadata, encodes H.264/yuv420p MP4 with fast-start, writes a poster and provenance manifest, and verifies duration and the absence of audio/subtitle streams. Every result is `reviewState:preview`; the script cannot approve or deploy it.
6. Review the full exported clip and crops, desktop/mobile playback and brand identity. Place reviewed candidate MP4/JPGs under `public/brand-clips/` and the manifest in `src/lib/broadcasts/product-films.json`. Preview records render only in development. Business review remains required before marking a clip `approved` and releasing.
7. After Robin approves the preview, run regression and production builds, release with rollback retained, and verify the public homepage, watch list, original detail routes and linked product pages. This task has not reached that approval/release step.
