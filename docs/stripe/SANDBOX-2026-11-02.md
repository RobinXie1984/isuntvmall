# Stripe Sandbox implementation and acceptance record — 2 November 2026

Status: **candidate implemented; real Stripe Sandbox success, decline, cancellation,
3DS, signed webhook settlement and replay checks passed**. No production deployment, production migration, live
payment, live key configuration, or main-branch push was performed.

## Reused architecture

The existing hosted Stripe Checkout adapter, Supabase/PostgreSQL order snapshots,
atomic stock reservations, named-role administration, finance operations and
payment ledger remain the system of record. No Connect platform, new payment
service, multi-tenant layer, or replacement checkout was introduced.

- The browser submits product IDs/quantities; authoritative prices are frozen by
  the database. Source-import and demo checkout protections remain intact.
- Merchant account and test/live mode are frozen into each order and verified
  against Stripe. Test credentials cannot masquerade as live credentials.
- Session creation uses the existing order-derived idempotency key. Uncertain
  provider responses preserve the reservation for reconciliation.
- A verified raw-body Stripe webhook settles the order. Success-page visits never
  write payment or inventory state; pending confirmations refresh read-only for
  at most 30 seconds.
- A repeated event/payment does not decrement inventory twice. Amount/currency,
  session, payment-intent and reservation discrepancies remain manual review.

## Candidate changes

1. Stripe SDK pinned to 23.1.0 and API `2026-10-28.endive`; supports restricted
   `rk_test_` / `rk_live_` server keys alongside standard secret keys.
2. Hosted Checkout uses Dashboard-managed dynamic payment methods, an optional
   frozen `STRIPE_PAYMENT_METHOD_CONFIGURATION`, and a stable integration label.
3. Async signature verification is compatible with the existing Worker build.
4. Delayed paid confirmations pass the same authoritative amount and active-stock
   checks. Delayed failure releases a pending reservation, but cannot downgrade
   a paid order. Payment after expiry/release remains manual reconciliation.
5. Local-test bootstrap now includes the email column required by the existing
   staff-directory migration and creates a new test SKU instead of trying to
   remove a protected demo flag.
6. Patched existing dependency advisories in the candidate: Next 16.4.4,
   eslint-config-next 16.4.4, Zod 4.6.7 and Vite 8.3.5. Runtime dependency audit:
   zero high/critical advisories, four moderate advisories retained in the receipt.
   This is a dependency audit result, not proof that every possible vulnerability
   is absent. The deployed site was not changed by these patches.
